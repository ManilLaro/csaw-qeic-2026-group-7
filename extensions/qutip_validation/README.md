## Reproduction

From the repository root, with `requirements-advanced.txt` installed (tested with QuTiP 5.3.1, qutip-qip, Python 3.13):

```sh
python extensions/qutip_validation/validate_dynamics.py
```

Runtime is about 3 s. Artifacts in `stages/stage_2/artifacts/` are only read.

## Assumptions

1. **Reduced model (supplied).** During the calibrated rectangular pulse, the Q1/Q4 pair evolves under
   H/ħ = ω ZZ/2 with ω = 2π·g_MHz/1000 rad/ns (`device_model.json` `reduced_assumption`,
   `local_subsystem.json` `dynamics_recipe`). This is a supplied challenge model, not derived here.
2. **Probe protocol** (`characterization.json`): prepare |++⟩, apply n back-to-back pulses of the calibrated
   duration t = 15.625 ns (`control_calibration.json`), then measure XI (X on Q1, identity on Q4).
   The pulse is integrated with `qutip.mesolve` (atol 1e-12) rather than evaluated in closed form.
3. **Couplings tested.**
   - g = 16 MHz from `model-20`, the value the calibration assumed.
   - g = 18 MHz from `design-21`, the current D21 device.
   - A minimax fit of g to the supplied probes.
4. **Decoherence** (optional run): amplitude damping and pure dephasing on both qubits, using
   T1 = 100 µs and T2 = 80 µs for Q1/Q4 from `noise_snapshot.json`. The snapshot says noise is excluded
   from the isolated probes, so this run only bounds its possible size.
5. **Verification companion** (`verification_protocol.json`): the 4-qubit local subsystem {Q0, Q1, Q2, Q4}.
   - Every qubit gets H, then RZ(φ_q).
   - Listed RZZ angles are applied on the edges inside the subsystem.
   - The target edge (1,4) instead uses the same calibrated-pulse dynamics as above.
   - Then ⟨X_Q1⟩ is measured.

   The edges that touch Q1 are exactly (0,1) and (1,4), so the other 28 qubits cannot affect ⟨X_Q1⟩.
   Q2 is included to show that a non-incident edge has no effect.

## Results

### 1. Characterization replay (8 probes, tolerance 0.004)

| n | supplied ⟨XI⟩ | QuTiP, g = 16 MHz (model-20) | QuTiP, g = 18 MHz (design-21) |
|---:|---:|---:|---:|
| 1 | −0.194090 | 0.000 | −0.195090 |
| 2 | −0.924880 | −1.000 | −0.923880 |
| 3 | 0.556570 | 0.000 | 0.555570 |
| 4 | 0.706107 | 1.000 | 0.707107 |
| 5 | −0.830470 | 0.000 | −0.831470 |
| 6 | −0.383683 | −1.000 | −0.382683 |
| 7 | 0.981785 | 0.000 | 0.980785 |
| 8 | −0.001000 | 1.000 | 0.000000 |
| **max abs residual** | | **1.001 ✗** | **0.0010 ✓** |

- The minimax fit of g to the probes using QuTiP dynamics gives **g = 18.000 MHz**, with max residual 0.0010.
  That is the declared fixed additive perturbation: the residuals alternate ±0.001 with n.
- The realized angle per pulse is **1.767146 rad = 9π/16**, against the intended π/2.
- With T1/T2 included, the largest change from the coherent result is 0.0019, below the 0.004 tolerance.
  Decoherence cannot produce the 0.2–1.0 differences between g = 16 and g = 18.

### 2. Verification companion ⟨X_Q1⟩

| | value |
|---|---:|
| observed (`observable_spec.json`, verification-X1) | −0.193199 |
| QuTiP, g = 16 MHz (what the calibration intended) | 0.000000 |
| QuTiP, g = 18 MHz (D21 device) | −0.193199 |

The D21 dynamics reproduce the observed correlator to 2×10⁻¹¹. The intended π/2 rotation is off by 0.193,
about 48 times the 0.004 tolerance.

### 3. "SX basis changes realize YY pair blocks"

`(SX⊗SX)† · RZZ(θ) · (SX⊗SX) = exp(−iθ YY/2)` holds to machine precision at θ = 9π/16. This block also commutes
with Z⊗Z. That explains why the main workload's parity observables (`total-parity`, `even-parity-marginal`) are
1.0 whatever the RZZ angle is, so they cannot detect this fault.

### 4. Repair validation

Two repairs from the Stage-2 analysis were simulated:
- **Corrected pulse length:** **13.8889 ns** at the D21 rate.
- **Corrected amplitude:** keep 15.625 ns and scale the rate by 16/18 = **0.8889**.

Both give ⟨XI⟩ = cos(nπ/2) = [0, −1, 0, 1, 0, −1, 0, 1] exactly (max deviation 0), and both return the
verification correlator to 0 (−3×10⁻¹¹).
